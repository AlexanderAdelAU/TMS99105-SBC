SHELL 6.5 - internal commands in their own pages
================================================
Core drops from 7660 to 6418 bytes; 1774 free below the BDOS (was 532).
Each of the nine commands now lives in its own 4096-byte page of
segment D and may grow to fill it without touching the core or any
other command.  A 4x DIR is now a non-event.

FILES
-----
  SHELLV65.A99   the core (built from SHELLV64)
  DIR.A99 SAVE.A99 ERA.A99 REN.A99 MKDIR.A99 CHDIR.A99 RMDIR.A99
  LOAD.A99 TYPE.A99   one per command, each AORG >D000, INCL "CORE.INC"
  MKCINC.C       generates CORE.INC from the core's listing
  CORE.INC.sample  what MKCINC produced here, for reference
  MAKE_SHELL65.bat, MAKE_SYSGEN65.bat

BUILD ORDER (see MAKE_SHELL65.bat)
----------------------------------
  1. R99 SHELLV65 L-H-              assemble core, keep listing
  2. MKCINC SHELLV65.L99 SHELLV65.A99 CORE.INC
  3. R99 <each command> H-          each INCLudes CORE.INC
  4. hex each .R99, then SYSGEN

Rebuilding the core changes core addresses, so ALWAYS re-run MKCINC
and reassemble ALL commands after any core change.  MKCINC withholds
every core address >=D000, so if a core routine a command needs ever
drifts above D000 the command fails to assemble - that is the guard
working, not a spurious error.

HOW IT WORKS
------------
  ICLIST: name, 0, page byte, entry word.  Page 0 = resident,
    2-10 = own page, >FF = failed to load.
  ICMD: page 0 runs in place; else MAP_SET segment D -> page,
    PSEL_EN, B *R2 (>D000).  R2/R3 preserved, so TYPE's arg survives.
  RETURN / NEXTCMD: PSEL_DIS, then D back to page 0.
  BDOS gate >02F6 (PSEL_DIS / CALL / PSEL_EN) never touches the map,
    so a command's CALL @BDOS works unchanged and D stays mapped.
  LDCMDS (cold start): reads each NAME.SHC into its page; a missing,
    empty, oversized, or non-"B @" file marks the entry >FF.

VERIFIED BY ASSEMBLING (your K&R R99)
-------------------------------------
  core clean, 6418 bytes, ends >D911
  all 9 commands clean, each starts B @ at >D000, none over its page
  no PSEL opcode survives in any command page
  every command's object = original apart from the intended edits
    (LOAD: debug strings renamed, +>C000 guard; TYPE: TINCHAR gate)
  everything a command reaches is < D000 (checked on the listing)
  ICMD, RETURN, NEXTCMD decoded from the assembled bytes
  NEXTCMD reads PROCSW (>D574) only after D is back on page 0

NOT VERIFIED - needs the hardware.  Test in this order:
  1. Boot.  Watch for any "--Cannot load command X" at startup.
  2. DIR                       (page 2)
  3. TYPE somefile             (page 5; paging, its own console input)
  4. MKDIR t / CHDIR t / ... / CHDIR .. / RMDIR t   (pages 7,8,9)
  5. SAVE / ERA / REN          (pages 3,4,10)
  6. LOAD an EXE               (page 6)
  7. SMALLC99 STRESS -V, R99, LINK99, STRESS   (nothing changed here)
  8. XMODEM, DIR2              (external, unaffected)

If a command misbehaves, the DBG_LOG dump and the "--Command not
loaded" / "--Cannot load command" messages tell you which page.
SHELLV63 remains your fallback; keep its .H99.
